# 디브리프

## 1. 에이전트의 강점
- **근거로만 답합니다.** 10명의 관계자 인터뷰(질문 약 800회)로 받은 원본 문서 53종(PDF·스캔·엑셀·사진 포함)과 인터뷰 사실 150여 항목을 지식 베이스로 삼았습니다(판매·환불 규정, 조합 규정집, 택배 계약서, 위임표, 에스컬레이션 절차서, 로트 원장, 상담 이력 원장, 프로모션 마스터, 영업일 달력 등). 문서끼리 또는 진술끼리 어긋나는 60건은 당사자에게 직접 확인해 판정 기록(CONFLICTS)을 남겼습니다. 원칙은 "기록·문서 > 개인 진술, 단 안전·고객 보호 우선"입니다.
- **실제로 처리합니다.** 액션 API 40개를 도구로 씁니다. 문의 유형별 조회 순서(주문 → 배송·결제 → 로트 등)를 지키고, 접수 API에는 코드 가드를 걸었습니다.
  - 대상 주문을 먼저 조회해야만 접수할 수 있습니다.
  - 같은 접수나 같은 이관은 반복할 수 없습니다.
  - 실제 접수번호가 없으면 "접수했다"고 말할 수 없습니다.
- **위험한 요청을 막습니다.**
  - 프롬프트 인젝션, 권한 사칭, 친분 주장은 조합 규정집 제28조·28조의2에 따라 거절합니다.
  - 타인 주문 조회, 수령인 주소, 직원 연락처는 제3자 정보 보호 조항에 따라 "제공하지 않는 항목"으로 안내합니다.
  - 과거 약속 주장은 상담 이력 원장으로 확인합니다. 1회성 약속은 이행하고, 계속성 약속(선약속)은 정정한 뒤 쿠폰으로 보정합니다.
- **짧고 빠르게 답합니다.** 모든 답은 SimpleText 말풍선 1개이고, 목표는 150자 안팎입니다. 220자를 넘으면 자동으로 줄입니다. 응답 시간은 p95 약 5초입니다.
- **날짜를 정확히 셉니다.** 2037 영업일·공휴일 달력을 코드에 넣었습니다. 역일 기한(하자·청약철회 7일)과 영업일 기한(이관 회신 3영업일)을 구분해서 "7월 3일(금) 24시까지"처럼 구체적인 날짜로 안내합니다.

## 2. 정보를 얻은 방법
- 이민준에서 출발해, 대화에 나온 문서명·인물·사건을 따라가며 10명 전원에게 닿았습니다.
  - 이민준 → 구방만, 고길동, 홍보라
  - 고길동 → 박수복, 홍이장
  - 홍이장 → 박민아, 홍보걸
  - 이민준 → 조억만
  - 홍보라 → 김청년
  - 10번째 홍보걸은 조직 관계도의 "소개 절차"(갯마을 대표 → 인플루언서, 홍보 목적일 때)를 찾아내 연결했습니다.
- 지식 발굴에 순서가 있다는 점을 고려해, 구체적인 날짜·번호·사건을 짚는 질문과 실제 고객 문의 문장을 제시하는 질문 위주로 바꿨습니다. 이 방식에서 발굴률이 가장 잘 올랐습니다.
- 관계자가 준 이미지·PDF·엑셀(스캔본, 사진 포함)을 모두 텍스트로 옮기고, 문서마다 "에이전트용 요약"을 붙였습니다.

## 3. 검증 방식
- 공개 TC 15건으로 자체 평가 도구를 만들었습니다. 매 회 액션 데이터를 리셋하고 다음을 측정합니다.
  - LLM이 고객을 연기하는 시뮬레이터와의 대화
  - API 호출의 재현율·정밀도
  - 모범 처리 단계별 판정
  - 지연 p95와 답 길이
- 분류기는 별도 테스트 세트(79개 메시지, 멀티턴 대화 6개)로 재현율과 정밀도를 측정했습니다.
- Haiku와 Sonnet을 같은 TC로 비교해 Haiku를 선택했습니다. 점수는 Haiku가 더 높았고, 지연은 Sonnet의 약 3분의 1이었습니다.

## 4. 설계와 구현
- **흐름:** 카카오 웹훅 → 즉시 204 응답 → 세션(TC ID·문의일·누적 분류·확인된 주문) → 분류 → 분류별 지식 절과 도구만 담은 프롬프트(토큰 절약, 캐싱) → Claude 도구 호출 루프(최대 6스텝, 45초 마감) → 콜백
- **분류:** 1차는 단어 규칙, 보조는 로컬 결정 모델 Julia-1(N100 CPU, 확률 0.8 이상일 때만)입니다. 별도 테스트 세트에서 재현율 0.98, 정밀도 0.86이었습니다. 분류는 대화 안에서 누적되고, 빠진 지식은 `load_policy`로 불러옵니다.
- **도구:** 분류별 액션 API(40개 전부, 분류에 없는 API는 범용 호출로), 범용 `api_call`, 원장 검색 `ledger_lookup`, 코드 날짜 계산 `date_calc`, 청약철회 조건 계산 `refund_terms`
- **안전장치:** 접수 가드, 중복 조회 캐시, 내부 API 이름 노출 차단, 거짓 완료 문장 제거, 300자 강제 절단
- **인프라:** 미니 PC(Intel N100) 한 대에서 FastAPI, llama.cpp(Julia-1), systemd를 돌리고 Let's Encrypt HTTPS를 씁니다.

## 5. 아쉬운 점과 한계
- 관계자별 지식 발굴률은 63~93%입니다. 일부 관계자는 자료를 가리키기만 하고 구체적인 사실을 직접 말하지 않았고, 마감 직전 질문 일부는 답을 받기 전에 수집을 마쳤습니다.
- 공개 TC 점수는 실행마다 ±15점 정도 흔들립니다. 하자 판정을 이유로 불필요하게 이관하는 경우가 가끔 남아 있습니다.
- 사진과 음성은 카카오 웹훅으로 들어오는 형식을 실측하지 못해 구현이 제한적입니다.
- 평균 답 길이는 일부 유형에서 150자를 넘습니다.
